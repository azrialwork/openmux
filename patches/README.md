# Patches

This directory holds the entire delta that `openmux` carries on top
of the upstream baseline pinned in `../upstream.json`.

## Rules

- One logical change per patch file.
- Files are named `NNNN-short-description.patch`, numbered in apply
  order (`0001-...`, `0002-...`, ...).
- `series` lists the patch filenames in apply order, one per line.
  Lines starting with `#` and blank lines are ignored.
- Every patch is listed in the table below with what it does and why.
- Preferred format: `git format-patch` output against the pinned
  baseline commit, so authorship and the commit message survive.
- A patch that no longer applies cleanly on the pinned baseline
  fails CI — fix the patch, never the baseline pin, to resolve it.

| `0002-remove-web-gui-and-gui-packages.patch` | Deletes the web GUI and the GUI-only packages: `packages/app`, `packages/ui`, `packages/session-ui`, `packages/gui-plugins` and `packages/stories`. | Same CLI/TUI-only delta as above. |
| `0003-remove-desktop-docs-sdk-and-other-envs.patch` | Deletes the Electron desktop app (`packages/desktop`), the docs site (`packages/web`), the SDK (`packages/sdk`), the VS Code extension (`sdks/vscode`), `packages/stats`, and the desktop browser plugin (`packages/plugin-browser`). | Same CLI/TUI-only delta as above. |
| `0004-remove-all-references-to-deleted-envs.patch` | Removes every reference to the deleted environments in the remaining tree: the web UI embedded into the CLI build and served by its server (`app-assets`/`web-ui` bundling), the CLI `pair` and `acp` commands, the server pairing endpoints, the plugin GUI SDK and GUI-bundle plumbing, the workerd server entry, root workspaces/scripts/catalog and the regenerated `bun.lock`, plus CI/release/nix/docs references. The internal API server the CLI/TUI run on stays; it now serves only its API. | Same CLI/TUI-only delta as above — deletion is total, references included, so nothing in the remaining tree points at an environment that no longer exists. |
| `0005-keep-only-opencode-free-models-and-custom-providers.patch` | Removes every built-in provider and model except the OpenCode Free Models and user-defined custom providers: the bundled models.dev snapshot is trimmed to provider `opencode` with only its 47 free models, the runtime models.dev fetch, the build-time live-catalog bundling and the persistent catalog cache are removed, catalog ingestion drops every non-`opencode` provider and every non-free model regardless of source, the provider adapters in `packages/ai` and the provider-specific core plugins (GitHub Copilot, Modal, Claude Agent, Bedrock, Azure, OpenRouter, xAI, the OpenAI/Codex OAuth plugin, local-server discovery, and the other built-in provider plugins) are deleted, and `disableFree` (`OPENCODE_DISABLE_FREE_MODELS`) is removed so free models always remain. Custom providers and models defined in config keep working through the kept generic adapters (Anthropic, OpenAI, OpenAI-compatible and the OpenCode decisions entrypoint). | Boss's second patch decision: openmux ships only OpenCode Free Models built in; everything else a user wants comes from their own config. Deletion is total — catalog, enforcement in code, and adapters — not UI hiding. |
| `0006-remove-per-model-system-prompts.patch` | Deletes the six per-model system prompt files in `packages/core/src/plugin/system-prompt/` (`anthropic.txt`, `gpt.txt`, `gpt-astra.txt`, `kimi.txt`, `meta.txt`, `trinity.txt`) and the built-in prompt plugins in `packages/core/src/plugin/optimize.ts` that selected them by model id (gpt/gpt-astra, claude, kimi, trinity, muse), including their registration in the builtin plugin list. Every model now uses the single base system prompt in `packages/core/src/session/runner/prompt/system.txt`, which keeps its name and content. `resolveModel` in `optimize.ts` stays (the identity and warming plugins use it), as do the intentionally disabled tool-curation plugins. Tests that asserted the deleted per-model prompts were rewritten to assert the single base prompt, and the recorded session-runner cassette was updated to the request the patched code actually sends. | Boss's third patch decision: one system prompt for every model — the per-model prompt variants are eliminated, focus is single. |
| `0007-restructure-built-in-tool-descriptions.patch` | Restructures the top-level description of every built-in tool into one consistent, scannable form — an opening line stating what the tool does, a structured details section carrying every fact, rule and limit of the original (all of them preserved, plus code-grounded detail such as real defaults and failure behaviour), and a closing `Batching:` section stating the tool's batch/parallel call priority. The batching guidance is grounded in the runner's actual execution model: the session runner forks each tool call in a step into its own fiber and runs the block's calls concurrently (`packages/core/src/session/runner/step.ts`), file mutations serialize their read-modify-write under a per-path lock (`FileMutation.withLock`, so parallel calls are safe across different files but must be sequenced for the same file), reads take no locks, `todowrite` replaces whole state (one call per block), and `question` batches through its own `questions` array. Covers the inline descriptions in `packages/core/src/tool/plugin/*.ts` (edit, read, write, glob, grep, shell, skill, subagent, question, webfetch, websearch, experimental_image_generate, the artifact, MCP-resource, session/worktree/models and schedule tools), the two external description files `packages/core/src/tool/patch.txt` and `packages/core/src/tool/todowrite.txt` (in patch.txt the envelope format, headers and example are preserved byte-for-byte), the `opencode` namespace description, and the Code Mode `execute` tool description in `packages/core/src/codemode/tool.ts`. Total description text grows from 9,891 to 24,828 characters (+151%) — growth was explicitly allowed. No tool logic, names, parameters, schemas or per-parameter descriptions change; `artifact_create`'s provider-rendered description is untouched; the one test that asserts a description verbatim (`tool-execute.test.ts`) was updated to the new text. | Boss's fourth patch decision, revised (superseding the earlier tighten-only direction): tool descriptions should be more structured, more detailed and clearer while remaining strictly factual, and every description must state the tool's batch/parallel priority so OpenCode's parallel tool execution is used to best effect. |
